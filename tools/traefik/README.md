# Traefik autogen import script

**Overview**

**Goal**: Scan Proxmox container descriptions and automatically generate Traefik dynamic configuration and local DNS overrides so services become routable with minimal manual configuration.

**What it does**: Produces Traefik YAML files under `/etc/traefik/dynamic/` and syncs DNS records to AdGuard Home to point public and private domains to the correct targets.

**Features**

- **Automatic route generation**: Creates routers, services and middlewares for containers annotated in their description.
- **TLS-ready**: Routers are created with the `websecure` entrypoint and a cert resolver so Let’s Encrypt can be used.
- **Security mappings**: Container `security` tags map to middleware (OAuth, basic auth, internal-only, etc.).
- **WebSocket-safe**: Routes that require WebSocket upgrades are generated without the header-injection middleware and set `passHostHeader: true`.
- **AdGuard DNS sync**: Syncs public domains to the Traefik VIP and creates internal `.lan` records that point to container IPs for internal service discovery.
- **Credentials**: Use an external `import.env` for secrets.

**How container descriptions work**

The script looks for INI-style `[web]` sections inside the Proxmox VM/LXC `description` field. Each `[web]` subsection defines a route. Supported keys:

- **domain**: Hostname to route (FQDN). Creates a Traefik host rule.
- **port**: Destination port on the container (required for HTTP routes).
- **security**: One of `oauth`, `public`, `private`, `password`, `auth`. These map to the script's predefined middlewares: `oauth` -> `security-oauth`, `private` -> `allow-internal`, `password` -> `auth-basic`, `auth` -> `authentik`.
- **proto**: `http` or `https` (affects service scheme and serversTransport).
- **ip**: Override the container IP when tags do not provide it.
- **dns**: If present, treated as a DNS-only record (no Traefik route).
- **websocket**: `true` to enable WebSocket-friendly routing (skips headers).

Example description fragment:

```ini
[web]
domain = app.example.com
port = 3000
security = oauth
proto = http
websocket = true
```

Automatic hostname and DNS behavior

- **Automatic `.lan` records**: For every container the script automatically builds a `.lan` record from the container hostname for internal service-to-service name resolution. It lower-cases the hostname and applies tiered deduplication when collisions occur:
	1. `hostname.lan` (if unique)
 2. `hostname-<pve_alias>.lan` (if needed)
 3. `hostname-<pve_alias>-<vmid>.lan` (fallback, guaranteed unique)

- **`dns = ` (additional DNS-only entries)**: If a `[web]` subsection contains `dns = some.name.local` the script creates an *additional* DNS-only record (no Traefik router) in AdGuard mapping `some.name.local` -> IP. This is separate from the automatic `.lan` record. The IP used is `ip =` in the same section (if present and private), otherwise falls back to the IP from VM tags (see "IP source priority" below).

IP source priority

- The script determines a container IP using the following priority:
	1. IPs listed in the container tags (first matching `192.168.x.x` address)
	2. `ip =` from the `[web]` section that matches the container hostname
	3. If neither yields a private IP the script will not create a `.lan` record for that container

This behavior avoids picking up non-LAN addresses (Tailscale, Docker bridges) and keeps `.lan` entries pointing to routable LAN addresses.

**Traefik output**

- **Files**: `autogen-<node>-<hostname>-<vmid>.yml` in `/etc/traefik/dynamic/`.
- **HTTP section**: The script writes `http.middlewares`, `http.routers`, and `http.services` blocks. For `https` backends it writes `serversTransports` entries with `insecureSkipVerify: true` and `serverName` set to the domain.
- **Middleware**: A `forward-headers-<route>` middleware is generated by default to inject headers required for some services. When `websocket=true` this middleware is skipped to preserve upgrade headers.

**AdGuard DNS sync**

- **Public domains**: The script syncs discovered domains to the Traefik VIP so external requests resolve to Traefik. This is done by calling the AdGuard Home rewrite API (`/control/rewrite/add`).
- **.lan records**: Internal `.lan` records are generated to point directly to container IPs for service-to-service access inside the LAN. A tiered deduplication ensures unique names (`hostname.lan`, `hostname-node.lan`, `hostname-node-vmid.lan`).
- **Pruning**: Orphaned rewrite rules that match the managed IPs are pruned.

**Traefik VIP detection & safety**

- The script attempts several methods to determine the Traefik sync target IP: config file VIP, keepalived config parsing, inspection of interfaces, and a hostname-based fallback. You can override this by setting `DEFAULT_TRAEFIK_VIP` in the config file.

**Configuration**

Provide secrets and endpoints via `/etc/traefik/import.env` or `./import.env`. Copy the provided example and edit values:

```bash
cp import.env.example /etc/traefik/import.env
# then edit /etc/traefik/import.env and set real values
```

Important variables (see `import.env.example`):

- **PVE_SERVERS_RAW**: Newline-separated entries of the form `alias|https://pve.example.com:8006/api2/json|PVEAPIToken=user@pam!token=...`.
- **ADGUARD_PRIMARY**, **ADGUARD_SECONDARY**: AdGuard Home hosts/IPs.
- **ADGUARD_USER**, **ADGUARD_PASS**: AdGuard credentials.
- **DEFAULT_TRAEFIK_VIP**: Optional override for the sync target IP.

**Running**

- Test run:

```bash
sudo /bin/bash import.sh
```

- Cron example (run every minute):

```cron
* * * * * /bin/bash /path/to/import.sh >> /var/log/traefik-autogen.log 2>&1
```

**Security**

- **Do not** commit `/etc/traefik/import.env` to version control.
- Use least-privilege API tokens and rotate them regularly.
- Restrict access to the script and generated YAML files to the Traefik service account.

**Files in this folder**

- **import.sh**: Main script that connects to Proxmox, generates Traefik config and syncs AdGuard (`import.sh`).
- **import.env.example**: Example configuration (`import.env.example`).
